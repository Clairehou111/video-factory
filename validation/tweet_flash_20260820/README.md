## 已验证结论

1. 画面轨预先制作为原生 1080x1920 MP4 时，MPT 不会对其加入缓慢放大，也不会产生黑场转场。
2. 用 SRT 的 cue 起点排 Shot 转场，可使第二、三段分别在 1.53 秒和 5.41 秒切入，和旁白语义对应。
3. MPT 的圆角字幕可用，但当前字体和背景偏大，会压到证据画面的底部；生产版须把字幕安全区作为 Shot 版式输入，而非后期猜测位置。
4. 真 crossfade 要在 `FlashTrackBuilder` 中完成；MPT 的 `fade-in`/`fade-out` 不能替代它。

## 新的视觉规则（参考片 + Tweet 卡）

1. 顶部固定为强标题与辅助标题；中部是带真实作者、日期、原文、译文和互动字段的 Tweet 重绘卡。来源 URL 只保存在证据记录中，不占用画面底部。
2. 采用深蓝渐变与蓝色高光；底部固定为一句可独立成立的事件结论，字幕使用白字深色描边，禁止圆角黑色字幕底板。
3. 每个快报仍由语义 cue 驱动的静态 Shot 与真 crossfade 构成，不使用缓慢放大或自动 Ken Burns。
4. 重绘不是伪造：卡内每一个账号字段、互动数和原文都必须从当前采集证据填充；采集不到就省略，不得填默认示例值。
5. 固定 footer 不是来源栏，而是让用户首屏就能读懂“发生了什么”的结论栏；它在整支片中不移动、不随镜头切换。

## 叙事技术号规则（本轮确认）

1. 原帖不是逐段搬运：它是事件证据，全文应在同一张可读的 Tweet 卡中出现一次。
2. 后续镜头要把事件讲清，并给出明确的技术号判断。本样片的判断是：当用户不再学习软件、只需交代目标，Codex 就不只是开发工具，而是在接手真实任务。
3. 标题和观点的强度由证据决定；有一手发布、性能数据或产业影响的事件可以使用更强的判断。单一用户故事则以“信号”“开始”“正在发生”这类准确表述为宜。
4. 视觉采用深蓝渐变与蓝色高光，去除网格；字幕保持无底板白字深描边。

## 视频号 10 秒快报的验证规则

1. 不做片头、Logo 或自我介绍：首帧直接给事件冲突，前三秒必须让人知道“谁遇到了什么问题”。
2. 本样片的 9.85 秒排程：0–4.38 秒完整原帖，4.38–7.71 秒给出可执行动作，7.71–9.85 秒给出技术号判断并立即结束。
3. 发布后在视频号创作者中心/视频号助手中同时看 3 秒播放率、完播率和逐秒流失曲线；保留相同题材的 10 秒与 20–30 秒版本做 A/B，不以单一行业均值决定时长。
4. 语音：优先 Yunxi 男声；若需要明显的人格、口音或自然停连，应接入带音色设计的服务，或使用经过授权的真人样本，而不是无限提高 Edge 语速。

## 本轮声音结论

1. Yunxi（活泼男声）在 1.4 倍速下，完整短叙事的实际音频时长为 9.94 秒，可用于 10 秒技术快报。
2. Xiaobei 是辽宁方言、幽默女声；更有生活化个性，但同稿为 10.87 秒，且会把技术号语气带向轻松调侃。适合做可选人格包，不作为默认声音。
3. 无旁白版本必须让每张画面自身可读，音乐只负责节奏，不替代信息；适合用户已熟悉视觉模板、或原始证据文字足够有张力的内容。
4. 用户试听确认 1.4 倍速成片仍可接受进一步加速；1.7 倍速可在 10 秒内换回事件背景和完整观点。生产上应把语速作为镜头/字数排程变量，而不是先删掉叙事因果。
