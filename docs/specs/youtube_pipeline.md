# YouTube 视频处理流程规范

本文件描述当前实现。入口是 `YouTubeCollectionFactory.generate`；定时发现与候选接纳在 `src/video_factory/discovery.py`。这里的 LLM 指策划、翻译或审稿模型；stable-ts/Whisper 是音频模型；“确定性”指解析、媒体处理和可机械验证的合同。

| 环节 | 当前处理 | 主要决策者 |
| --- | --- | --- |
| 0. 监测与接纳 | 搜索、去重、来源及受众评分；失败候选进入重试或人工审核。Dashboard 手动重试进入单 worker 队列，立即持久化 `queued/running/succeeded/failed/interrupted`、阶段和短日志，避免同时点击时并发覆盖 discovery state；页面每 5 秒轮询。Dashboard 重启后按原 `created_at` 顺序恢复遗留的 queued/running 任务；若候选在退出前已生成则直接收敛为 succeeded。直接 `generate URL` 可跳过发现。 | 确定性状态机 |
| 1. 采集证据 | 获取 metadata 和英文 `json3`，保存原件与哈希。`TranscriptCue` 只是带时间的采集片段，不等于完整句子或最终字幕卡。 | yt-dlp、确定性解析 |
| 2. 路线分类 | 根据标题、频道、描述、章节和人物识别技术讲座、人物访谈、可信长会议或 study；显式模式可覆盖。 | 确定性分类 |
| 3. 策划选段 | 选择高光、标题、Hook、连续源区间及少量视频级术语；确定性合同检查范围和字段。 | 策划 LLM + 确定性合同 |
| 4. 语境术语 | 策划模型先提出 `translate/preserve`、本视频译法、至多两个备选和上下文依据；字幕阶段再只读固定选段，发现策划阶段遗漏且确实出现在源文中的新术语。独立审稿判断策略与目标本身，并可把疑似 ASR 错词判为“不是稳定术语”后删除提议。对于源字幕中与保留专名相近的拼写，代码只提出有限候选，独立审稿结合上下文批准 `source_variants` 后才可用于 ownership；字符距离本身不构成批准。没有上下文依据的旧缓存单个普通英文词不再作为视频级术语执法，回到逐卡上下文翻译，避免一个多义词在全片被强制成同一词义。若审稿响应漏项、重复或缺少必需字段，审稿器针对未变的提议原地重试一次；只有结构有效的语义否决才让翻译模型重提失败项，再交独立审稿复核。发现模型连续两次给出不在原文、重复或结构无效的可选提议，或某项重提后仍被独立审稿否决时，确定性代码归档并丢弃这些可选提议，继续让逐卡语义审稿把关，不因可选术语扩充阻塞整条视频。该发现调用拿不到标题、Hook、thesis 或候选范围，不能改变策划。 | 策划/翻译 LLM 提议 + 独立审稿 LLM + 确定性结构校验 |
| 5. 源词时间与访谈音频 | `json3` 解析保留每个字幕 fragment 的时间并验证它能逐词重建 cue；有效时直接写入稳定 `SourceWord`，缺失或异常才在 cue 内线性插值。访谈在策划后下载选中片段，并额外把权威 YouTube 英文交给固定提交的 stable-ts forced alignment；同一选段产出只读 ASR hypothesis。音频文字不覆盖 YouTube 英文。已裁本地媒体必须带 `source_clip` provenance，不能凭时长猜来源。 | JSON3 确定性解析；访谈另用 stable-ts/Whisper + 确定性降级 |
| 6. 联合分卡翻译 | 所有路线都先完成并冻结策划，再进入字幕阶段。technical、conference、study 还会在原始 cue 上冻结 Hook 文案与时间窗；最终只把 Hook 的 cue ID 映射到新卡，分卡不能重新选 Hook。已选 Bilibili/WeChat 范围的全部端点组成不重叠原子 scope，字幕卡不得跨最终剪辑边界；字幕阶段不会回写范围、标题、Hook 或 thesis。每个 scope 的连续词账本确定性划成不超过 150 词、通常约 120 词的首次翻译窗口；每个源词只进入一次。响应同时给出累计 source word 边界和中文。 | 确定性 scope/窗口 + 翻译 LLM |
| 7. 门禁与独立审稿 | 先检查 source word 恰好覆盖一次、顺序、1.2–7.5 秒、最多 28 个英文词、每秒 12 个阅读单位、真实字体三行布局、实体、数字、嵌套长词组和一致性。独立审稿以最多 24 卡且约 10k 字符的 core 分区工作，相邻各两卡仅作只读上下文；每个 core ID 首轮恰好审一次。局部自愈后，内容、词区间及左右相邻卡均未变化的通过结果在本次任务内复用，只复审变化卡及受影响邻卡。全序列一致性审稿仍看完整序列作为上下文，后续轮次用本轮变化卡、相邻卡和上一轮未解决卡作为关注范围；确定性代码不会丢弃审稿实际返回的其它实质问题。单个 scope 多分区时做紧凑全序列一致性审稿；存在多个剪辑 scope 时，再用各 scope 首尾和术语实际用法做跨 scope 独立一致性审稿。结构错误只重试同一审稿请求，不触发重译。一个 CJK 字形、一个拉丁文字词或一个标点各计一个阅读单位。 | 确定性门禁 + 分区独立审稿 LLM + 全局一致性审稿 LLM |
| 8. 局部自愈 | 首次翻译响应结构错误会带确定性错误反馈重试一次；若返回的边界严格递增但提前停止，已覆盖前缀不重译，代码只把未覆盖尾部交给 LLM 并重新验证完整 source word 覆盖。语义或显示失败时，前三轮把失败卡连同左右各一卡组成窗口，重叠窗口合并；翻译 LLM 可移动边界、改变卡数并重译，窗口外不变。时长、英文词数或三行布局超限会机械提高最小卡数并要求在超限源词范围内部新增边界；机械门禁要求新增拆分时不得同时冻结旧边界。若 LLM 连续三次没有在指定范围拆分，代码从该范围选择满足最短时长且最接近时间中点的固定词边界，再让 LLM 按固定边界重译局部窗口。进入固定边界阶段后，只把仍失败的卡交给 LLM，左右已通过卡仅作为只读上下文，避免修复别处时回归已正确译文；只有审稿明确指出边界、代词指代、悬空片段或相邻卡归属问题时，第 5 和第 9 轮才重新开放局部边界。纯术语、数字或措辞错误保持英文边界不变。前三轮可移动边界修复和一次固定边界修复后会先做独立最终裁决；裁决仍保留的同一非边界错误若在完全相同的卡片和译文状态下重复，确定性代码停止本 scope，保留 checkpoint 并让后续任务只重试该 scope，避免机械耗尽十二轮。返回卡数、每个边界和每卡目标术语都需精确匹配。最终审稿读取同一英文范围的历轮错误记录和完整序列，先消解自身相互矛盾的 actor/referent 或“实体/普通词”判断；代词依据完整因果链、收入/利润归属和组织的 singular-they 用法判断，不能默认最近名词。每轮处理全部仍失败的局部窗口，初始三轮可移动边界修复后最多十二轮有界语义自愈，其中最多两次按问题类型触发后期边界重议。全序列审稿若只因 JSON schema 错误失败，会对同一未变序列最多请求三次，并明确禁止逐卡复述。实体 ownership 标出术语、缩写和数字的源词位置，`translate` 术语另带源词位置和经审定的必需目标译法。音频数字冲突只有在前后各至少两个相同词锚定的单值局部 replacement 中才能配对，豁免绑定具体 source word occurrence；同值的其他出现仍受 ownership 保护。YouTube 单任务默认 LLM 请求硬预算为 400，仍受 5 美元成本上限约束；其它任务默认 200，也都可由环境变量收紧。 | 翻译 LLM + 独立审稿 + 确定性轮次/ownership 控制 |
| 9. 缓存与审计 | 每个完成局部审稿和确定性门禁的原子 scope 立即以内容寻址 checkpoint 原子落盘；输入绑定视频、路线、选段、源词账本、运行指导、完整术语决策和策略版本。后续 scope 失败时，重试可从当前任务或同视频旧任务恢复已完成 scope，只调用尚未完成的 scope。所有 scope 拼合并通过跨 scope 一致性审稿后，checkpoint 才提升到正式缓存；输入变化、文件损坏或重新校验失败都视为未命中。所有路线的其它新缓存同样必须匹配当前联合字幕策略、严格英文、中文、时间和完整术语决策。旧 cue 翻译缓存只作为字幕 challenger：保留原 `editorial_plan`，从当前英文重建字幕。发现重试若遇到缓存 translation plan 与本次权威字幕不匹配、访谈恢复出空词账本，或已选范围无法映射到任何字幕词，会保留字幕并在下一次有界尝试中明确移除旧 plan，重新策划与翻译；空 transcript 的失败 plan 不会成为候选。旧 plan 若是裁剪媒体原始时间线的唯一 provenance，移除它时也不再复用该本地媒体，而是按新选段重新下载，不能凭时长猜范围。完整模型请求、失败候选和 provenance 写入 `translation-audit.json`；plan/result 只保存哈希、大小和足以恢复及判定缓存的紧凑 trace。手动 `cleanup` 默认 dry-run，只允许删除超过保留期且未被发布、自审或当前候选恢复流程引用的失败任务；最近可恢复的 manifest/translation plan 和 scope checkpoint 必须保留。恢复扫描把 `glob` 与读取之间被 cleanup 删除的文件视为正常竞态并跳过。 | 确定性指纹、原子 checkpoint、归档、引用保护与 challenger 选择 |
| 10. 成片与发布门 | 建立 manifest，渲染双语字幕、导出 SRT，检查片长、画面、音轨、字幕、术语和版权依据。生产完成仍需人工发布审核。 | 确定性渲染验收 + 人工发布审核 |

## 访谈字幕合同

- `SourceWord` 保存稳定 ID、原始词、规范化词、经验证的 JSON3 逐词时间、可选音频时间、状态和置信度。最终卡片是连续 `[start_word, end_word)`；内部显示边界取相邻词时间的中点。只有 fragment 无时间、词序不能精确重建、时间越界或不单调时，才退回 cue 内线性插值；trace 分别统计 `json3_timed_words` 与 `linear_fallback_words`。
- YouTube 英文是发布文本来源。stable-ts 对齐现有英文，并为访谈选中时间窗生成独立只读 ASR hypothesis；低置信度、实体冲突和数字冲突在首次翻译前显式列为证据，不能静默改写英文卡。数字候选必须由同一个局部 `SequenceMatcher` replacement、唯一源数字及两侧稳定锚点共同证明；通常只接受唯一音频数字，音频把一个粘连数字拆成多个数字时，只有各项按序拼接后与源数字完全相同才允许按拆分后的数值翻译（如源 `8020`、音频 `80 20`、译文 `80/20`）。全局 source-only/audio-only 集合只作诊断。确定性数字 ownership 不把 `10erson` 这类与字母粘连的 ASR 残片当必需数字，同时禁止把残片原样复制进中文；残片的可见数字前缀可作为可选目标证据，因此 `10erson` 可按音频/语境译成“10 人”或“十人”，但不会强制必须出现阿拉伯数字。允许同卡英语月份按中文惯例写成数字月份（如 `September` → `9 月`），并允许范围尾部的 `%` 在自然中文中补到前项（如 `70 80%` → `70% 到 80%`），但没有对应月份或同卡百分比范围的新增数字仍失败。对齐结果必须全局单调并落在片段范围内，否则整段降级。媒体 SHA-256、SourceWord 账本哈希、stable-ts 提交/模型、音频 hypothesis 哈希和对齐策略进入证据指纹；完整词账本与 hypothesis 另存为 `source-word-ledger.json`。
- 22 个阅读单位是生成目标，不是硬上限。已删除 32 字门；硬门只有实际像素/三行、时长、英文词数和每秒 12 个阅读单位。混排英文按词计数，因此 `Palo Alto Networks` 计 3 个阅读单位，而不是按 16 个字母制造虚假的超速失败。
- 中文只承载实质语义：`um`、`uh`、`you know`、`I mean`、口语承接用的 `OK`、作为话语填充的 `like/well/so` 及只作强调音效的句首 `boom` 不要求逐字翻译；`OK` 不进入大写缩写实体 ownership。`[laughter]`、咳嗽、清嗓、音乐、掌声、呼吸等非语音说明从可发布卡排除。填充清理发生在独立审稿前，reviewer 把这些省略视为有意编辑，不判为漏译。
- 审稿按有序序列判断语义，不改写文案。每卡同时携带权威的半开 `source_word_range`；相邻非重叠区间即使文字相同也表示说话人确实重复，不能误判成系统重复卡。YouTube 英文仍是发布权威文本，但审稿会结合只读音频 hypothesis 理解其中明显的 ASR 拼写/空格残片，不要求中文逐字保留坏片段，也不要求改写英文；同卡完整词的大小写规范（如 `first robotics` → `FIRST 机器人`）不算实体跨卡移动，源文没有该词时仍失败。没有新增事实时，自然中文补出隐含中心词不算发明。修复只能由翻译模型在失败局部窗口完成；正常卡不会被全片 style repair 再次改写。
- `preserve` 术语仍以源字幕中的 `source` 判断卡片 ownership；逐卡门禁会在每轮自愈前报告源卡缺失或邻卡越界，最终术语合同再兜底，避免所有审稿结束后才发现而无法局部修复。对于至少 6 字符的单个拉丁产品名，代码可把一次插入、删除或替换的源词列为审稿候选；只有独立审稿结合上下文批准后，该 `source_variant` 才能把同卡 `Rooma` 归属给 `Roomba`。未批准的相近普通词（如 `strike` 与 `Stripe`）不做模糊 ownership，邻卡也不能借此移动实体。若独立审稿确认了不同的非中文发布拼写（如源字幕 `crowd strike`、目标 `CrowdStrike`），合同按审定 `target` 校验输出，不能反过来要求保留 ASR 的错误空格或大小写。
- `translate` 术语若审定目标与源词是同一书写形式（如 `token` → `token`），合同只要求保留该形式，不再同时报“必须出现”和“删除英文”。中英文混排目标允许排版空格差异（如 `暗token` 与 `暗 token`），语义目标本身仍须一致。
- 三轮可移动边界修复和精确逐卡重译后，独立审稿对剩余否决做一次只读裁决；只有实质遗漏、发明、主体/语气/范围变化、实体错位、误导性切分或不可理解中文可以继续阻塞，偏好性措辞、仅称“可能影响”的担忧及自称“无问题”的否决会被要求重新判断。裁决确认的新失败可触发第二次、也是最后一次固定边界局部重译。
- 视频级术语由 LLM依据上下文提议并由独立审稿确认。独立审稿同时检查 `preserve/translate` 策略和目标译法；“新兴”本身不能成为保留英文的理由，有清楚、自然中文表达时必须退回翻译模型重提并再次复审。代码不维护 `retrieval agent`、`recommendation agent`、`openweight`、`RL` 等逐词语义规则；确定性代码只处理审稿响应结构、source span、长词组遮罩、逐卡 `preserve` ownership、实体和全片一致性。缩写只有在本视频术语中被审定后才由代码强制目标形式；被判定为 `translate` 时，同卡出现经审稿的目标译法即可满足 ownership，不会再强制复制英文缩写。未进入术语表的缩写由独立审稿判断译义是否忠实，目标侧凭空新增的大写实体仍由确定性代码拒绝。较长术语拥有其内部较短词，避免嵌套条目重复执法。长度足够的拉丁文复合词可识别紧写/分写拼法变体，避免把同一词形误判成跨卡移动。
- 已审缓存以有序英文、中文和时间的内容哈希绑定 reviewer trace，并同时绑定审稿时的完整术语决策（策略、目标、备选、上下文依据和经审稿批准的源拼写变体）、严格的可发布英文源哈希、词账本、媒体 SHA-256 和对齐指纹。scope checkpoint 还绑定选段端点和运行指导哈希，加载时重新执行精确英文覆盖、术语、时长和布局门禁。可发布源保留标点、口头填充词和全部 spoken text，仅排除 `[laughter]` 等非语音舞台说明。缓存字幕或术语决策任一变化都不能沿用旧 verdict。若当前 YouTube 源文本与缓存不同，代码先按当前源重新解析术语，删除已消失条目并补回当前出现的已知/受保护项，再走术语复审和联合翻译。旧批准成片保持冻结；策略版本变化时生成 challenger，不能绕过新字幕门禁。
- `translation-audit.json` 保存完整重试历史；`translation-plan.json` 与 `result.json` 的 `translation_audit` 字段保存文件名、SHA-256、字节数和 schema。内联 trace 删除成功联合翻译的庞大 attempts；失败摘要保留失败卡、最终错误和尝试数，恢复逻辑无需读取模型正文。

## 旧步骤为何存在，以及现在如何处理

| 旧步骤 | 当时解决的问题 | 历史例子 | 当前处理 |
| --- | --- | --- | --- |
| cue 粗翻 | 早期 cue 直接作为最终字幕 | JSON3 会在 `how an`、`concept of` 中间断开 | 所有路线都不再粗翻；采集 cue 只用于策划和建立词账本 |
| 合并后重译 | 拼接旧中文会保留断句和错序 | `every` / `layer.`、悬空的“部署 agentic system 时” | 首次联合分卡直接看到完整上下文 |
| 固定卡再次翻译 | 英文边界变化后不能按比例切旧中文 | 实体或动作被移动到相邻卡 | 边界和中文在同一次响应中生成 |
| 末尾 style repair | 修复全片书面腔和字面翻译 | 它曾把已审卡改成 39 字，并造成 MLS 遗漏 | 删除正常路径的后置改写；问题进入局部联合自愈 |
| 翻译后局部 Whisper | 只有媒体到本地后才能核验可疑 ASR | 音频改字后需要再次翻译和复审 | 媒体和整段对齐前移；YouTube 文字保持权威，首次翻译已看到音频时序 |
| 单独语境术语复审 | 短 cue 可能绕过语义卡审稿，且字幕审稿若把术语表当成合同，会放过错误的 `preserve` 决策 | `retrieval agent` 与嵌套 `agent` 双重强制；可自然翻译的新术语被保留成英文 | 首次翻译前独立复审策略和目标；完整序列审稿继续检查实际用法 |

上述旧实现函数已经从生产模块删除；缓存读取只保留旧 step 名字符串用于识别已发布 incumbent，不会再次执行旧流程。

## 公共实现与依赖边界

- stable-ts 是受管 YouTube 运行环境中的固定外部依赖，通过窄 `AudioWordAligner` 调用；失败不会让可选音频能力阻塞 JSON3 降级。
- WhisperX 的“先词对齐再分行”、Subtitle Edit 的 CPS/像素/行数检查、VideoLingo 的目标语言后验校验用于设计参考，本项目自行实现合同和数据流。
- 不 vendoring、不复制公共仓库，也不让研究 clone 进入源码、构建、部署或运行路径。

相关实现集中在 `src/video_factory/youtube.py`、`src/video_factory/youtube_alignment.py` 和 `src/video_factory/youtube_runtime.py`；回归测试在 `tests/test_youtube_collection.py` 与 `tests/test_youtube_alignment.py`。
